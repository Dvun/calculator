# YieldPilot — калькулятор доходности

**React 19 · Vite 7 · TypeScript · Recharts · Lucide**

Версия **1.0.1**. Адаптивный трекер достижения финансовой цели в тёмном торговом стиле. Работает полностью в браузере и не требует сервера, регистрации, базы данных или API-ключей.

![Тема интерфейса](public/favicon.svg)

## Возможности

- Начальная сумма, цель, срок **1–730 дней** и дата старта. Денежные обозначения и выбор валюты отсутствуют: все суммы отображаются числами.
- Расчёт ежедневной доходности **по сложному проценту**.
- Полная таблица на каждый календарный день с ожидаемой прибылью и балансом.
- Галочка завершения дня открывает ввод **фактической прибыли, нуля или убытка**; приложение не записывает вымышленный результат.
- **Адаптивный** режим: пересчитывает необходимые ежедневные показатели на оставшийся срок после каждого фактического результата.
- **Фиксированный** режим: сохраняет первоначальные целевые суммы прибыли на каждый день.
- График с исходным планом, фактом и текущей проекцией; прогресс и статистика.
- Редактирование результатов уже завершённых дней. Отмена последней галочки, сброс результатов.
- Автоматическое сохранение всех данных через **localStorage**, восстановление при повторном открытии.
- Экспорт CSV, резервная копия в JSON и импорт JSON. Экспортируемые суммы не содержат обозначений валют.
- При обновлении с прежней версии имеющиеся результаты в `localStorage` и резервные копии JSON остаются совместимыми: старое поле `currency` игнорируется.
- Адаптивная верстка для настольного компьютера и телефона.

## Запуск локально

Требуется **Node.js 20.19+ или 22+**, npm.

```bash
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://localhost:5173`).

Проверка математических сценариев:

```bash
npm run test
npm run build
npm run preview
```

## Хостинг на Vercel (бесплатный статический сайт)

1. Загрузите этот проект в репозиторий GitHub.
2. В Vercel нажмите **Add New → Project** и импортируйте репозиторий.
3. Framework Preset: **Vite** (обычно определяется автоматически).
4. Build Command: `npm run build`, Output Directory: `dist`.
5. Нажмите **Deploy**. Сервер и переменные окружения не нужны.

Проект не использует серверные функции, поэтому подходит для статического хостинга. Актуальные условия бесплатных планов проверяйте у провайдера.

## Хостинг на GitHub Pages

Репозиторий должен содержать файлы проекта **в корне**. В проект уже включён workflow `.github/workflows/deploy-pages.yml`.

1. Создайте репозиторий GitHub, например `yieldpilot`, загрузите файлы и сделайте push в ветку `main`.
2. В GitHub откройте **Settings → Pages → Build and deployment** и выберите **GitHub Actions**.
3. После push откройте вкладку **Actions**, дождитесь успешного workflow `Deploy to GitHub Pages`.
4. Адрес сайта: `https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Workflow автоматически задаёт правильный Vite `base` вида `/имя-репозитория/`, иначе GitHub Pages может показать пустую страницу из-за неправильного пути к JS/CSS.

**Если домен корневой (`username.github.io`) или собственный**, в workflow замените строку `VITE_BASE_PATH: /${{ github.event.repository.name }}/` на `VITE_BASE_PATH: /`.

### Ручная сборка с нестандартным базовым URL

```bash
# macOS / Linux
VITE_BASE_PATH=/yieldpilot/ npm run build
```

В Windows PowerShell:

```powershell
$env:VITE_BASE_PATH='/yieldpilot/'
npm run build
```

## Как работает независимость пользователей

- У каждого браузера и устройства есть **собственное** хранилище `localStorage`, изолированное по домену сайта.
- Два человека на разных компьютерах не могут изменить результаты друг друга.
- Две вкладки сайта в одном браузере одного пользователя получают изменения через браузерное событие `storage`.
- Два человека **в одном браузере, с одним профилем браузера** разделяют данные и считаются одним пользователем. Для независимости на одном компьютере используйте отдельные профили браузера.
- Синхронизации **между компьютерами/телефонами нет**. Для переноса используйте экспорт/импорт JSON.
- Данные можно потерять при очистке истории/данных сайта, в приватном режиме, при удалении профиля браузера или если изменился адрес сайта (например, GitHub Pages → Vercel). Используйте резервные копии JSON.
- Никакие результаты не отправляются на сервер. **Не размещайте конфиденциальные суммы на общем компьютере**: любой человек с доступом к тому же профилю браузера сможет открыть страницу и прочитать данные.
- Если браузер блокирует запись в localStorage, страница сообщит об этом; резервная копия JSON позволит сохранить результаты вручную.

## Формула

Ежедневная ставка рассчитывается как:

\[
r = \left(\frac{F}{S}\right)^{1/n} - 1
\]

где:
- `S` — стартовый капитал,
- `F` — целевой капитал,
- `n` — число оставшихся дней.

В адаптивном режиме после дня с фактической прибылью/убытком изменяются `S` (фактический текущий баланс) и `n` (оставшийся срок); процент пересчитывается. Для будущих дней прибыль считается от соответствующего баланса, поэтому сумма дневной прибыли растёт при положительном проценте.

**Пример:** 100 000 → 150 000 за 30 дней ≈ **1,360725% ежедневно**. Первая плановая прибыль ≈ **1 360,73**, 30-й день доводит расчётный баланс до 150 000.

Округление отображаемых числовых значений: до 2 знаков после запятой. Последний расчётный день корректирует копейки, чтобы в математической модели получалась точная целевая сумма.

Фиксированный режим поддерживает абсолютные суммы дневной цели, рассчитанные при создании плана. Если фактические результаты отличаются, итоговая проекция в этом режиме тоже может отличаться от первоначальной цели.

**Это математический план требуемой доходности, а не прогноз, гарантия или торговая рекомендация.** Доходность не учитывает риск, комиссии, налоги, проскальзывание и невозможность получать одинаковый процент каждый день.

## Важные ограничения

Результаты считаются последовательно: нельзя отметить день №5, пока не отработаны дни №1–4. Это защищает расчёт текущего баланса и адаптивного сложного процента от неоднозначности. Для редактирования результата прошлого дня откройте его фактическую сумму; для отмены галочки снимите сначала последний день.
