## Обновление на Vercel

1. На действующем сайте убедитесь, что ранее внесённые результаты сохранены в Firestore.
2. Распакуйте архив и замените исходные файлы репозитория, **не затирая свой локальный `.env.local`**.
3. Выполните `npm ci`, `npm run test`, `npm run build`, затем `git add -A && git commit -m "YieldPilot v2.3.2 compact calendar and journal" && git push origin main`.
4. Vercel использует прежние Environment Variables `VITE_FIREBASE_*`; менять правила Firestore и создавать новую БД не нужно.

## Важное предупреждение: Firebase Admin SDK

Предоставленный файл `calculator-app-…-firebase-adminsdk-….json` содержит **private key service account**. Он **не используется**, **не копируется** в приложение и **не включается** в ZIP. Если ключ был передан за пределы защищённого окружения, удалите/отзовите этот ключ в Google Cloud IAM → Service Accounts → соответствующий сервисный аккаунт → Keys. Для клиентской архитектуры создавать ему замену не нужно. Не вставляйте этот JSON в `.env`, GitHub или Vercel.

Для React нужен другой набор настроек — **Firebase Web SDK config**. Его `apiKey` по дизайну публичен; он не предоставляет доступ к пользовательским данным без Firebase Auth и Firestore Security Rules.

## Firebase Console: что сделать один раз

1. Откройте Firebase Console → проект **calculator-app-c537d** → Build → **Authentication** → Sign-in method. Включите **Email/Password**.
2. В Authentication → Settings → **Authorized domains** добавьте домен вашего Vercel-сайта (и localhost для разработки при необходимости).
3. Build → **Firestore Database** → Create database. Выберите подходящий регион и создайте базу в безопасном режиме.
4. Firestore Database → **Rules**. Скопируйте файл `firestore.rules` из архива и нажмите **Publish**. Не оставляйте тестовое правило `allow read, write: if true`.
5. Project settings (шестерёнка) → General → **Your apps** → добавьте Web App (`</>`), если его нет. Скопируйте `firebaseConfig`.
6. Скопируйте `.env.example` в `.env.local` и заполните поля `VITE_FIREBASE_*` значениями из **Web App**. Поле `apiKey` Web SDK — не `private_key` и не `private_key_id` из Admin SDK JSON.
7. Для Vercel в Project → Settings → **Environment Variables** добавьте те же `VITE_FIREBASE_*`, примените для Production и Preview по необходимости и сделайте **Redeploy**.

**Не добавляйте файлы `.env.local` и service-account JSON в Git**. Vite встраивает все `VITE_*` значения в JS-бандл клиента, поэтому туда допустимо помещать только **публичную Web-конфигурацию**.

## Как теперь работают аккаунты

- Регистрация: **email (используется как логин) + пароль**, минимум 8 символов; вход и восстановление пароля Firebase Auth.
- После входа загружаются **только документы данного пользователя**. Доступ из чужой учётной записи блокируют Firestore Rules по `request.auth.uid`.
- Записи хранятся как `users/{uid}/goals/{goalId}`, `users/{uid}/journal/{journalId}`, `users/{uid}/meta/preferences`. Пары цель/дневник связаны по `goalId`.
- Изменения в Zustand отправляются в Firestore автоматически. Статус верхней панели показывает «Сохраняется», «Сохранено» или ошибку. Перед выходом ожидается подтверждение записи в БД.
- На другом устройстве войдите с тем же email и паролем — цели и дневник будут загружены из Firestore.
- Созданные до обновления `localStorage`-данные **не подмешиваются** к чужим аккаунтам: если база нового аккаунта пустая, появляется предложение **«Перенести в облако»**. Оно требует явного подтверждения; оригинальные локальные записи не удаляются.
- Данные облачного пользователя не хранятся через старый общий Zustand persist. Системные разделы настроек/интеграций остаются скрытыми; в текущем верхнем меню кнопки экспорта JSON нет.

## Ограничения версии

- Требуется соединение с Firebase. При проблеме записи появляется ошибка; серверную запись нельзя считать успешной до подтверждения.
- На нескольких одновременно открытых устройствах изменение **одной и той же цели** может привести к принципу «последняя запись победила». Перезагрузка/возвращение на вкладку подтягивает изменения облака, если нет несохранённых правок. Совместное редактирование одной записи в реальном времени — отдельный будущий этап.
- Удаление цели и связанных заметок отправляется одной группой операций при обычных объёмах; очень крупный импорт делится на Firestore batches по 300 изменений, которые не атомарны между партиями.
- Файлы с приватными Admin credentials, пользовательские пароли и хеши **не сохраняются** в JavaScript, Zustand, Firestore-документах или Git.
- Встроенные калькуляторы не торгуют автоматически и не гарантируют доходности.

## Структура

- `src/services/firebase.ts`: Web SDK конфигурация.
- `src/services/cloudSync.ts`: сохранение отдельных документов, загрузка из Firestore и контроль синхронизации.
- `src/components/AuthGate.tsx`: регистрация, вход, восстановление пароля.
- `src/state/store.ts`: локальное состояние Zustand **только авторизованного аккаунта** и чтение старого `localStorage` исключительно по запросу пользователя.
- `firestore.rules`: изоляция документов каждого Firebase UID.
